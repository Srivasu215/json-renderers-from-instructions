Why JSON as the Source of Truth?

Why build an entire rendering architecture on JSON instead of JSX, HTML templates, or custom DSLs? Because JSON is the only truly universal medium in modern computing.

1. Zero Compiler Baggage

JSX and custom template languages require massive build-tooling pipelines: Babel, Vite, esbuild, transpile passes, and bundle watchers. JSON is natively parsed by every JavaScript engine on earth at runtime with zero build step.

2. Cross-Language & Database Native

A PostgreSQL jsonb column, a Go backend, a Python FastAPI microservice, a WebSocket stream, or an AI agent can all emit JSON directly. No backend needs to know anything about the DOM.

3. Headless Inspectability & Testing

Because JSON is pure data, you can log it, diff it, serialize it, save it to disk, or test it in unit tests without spinning up a browser, headless Chrome, or JSDOM.

4. Safe by Default

Unlike raw HTML strings injected via innerHTML, JSON carries pure declarative structure with no executable script vectors during transmission.

Both Sides of the Contract Are JSON

In this architecture, not only is the business data JSON (data.json), but the layout blueprint is also JSON (columns.json and instructions.json). 

// Both input and blueprint live as pure JSON:
{
  "columns": [
    { "name": "Item Name", "field": "itemName" },
    { "name": "Category",  "field": "category" }
  ],
  "data": [
    { "itemName": "High Tensile Bolt", "category": "Fasteners" },
    { "itemName": "Galvanized Wire",    "category": "Raw Materials" }
  ]
}
