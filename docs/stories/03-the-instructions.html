The Instructions: Recipes as Data

In traditional codebases, layout logic is hardcoded inside procedural JavaScript loops. In this architecture, the instructions are themselves pure JSON.

1D Transformation

Single Instructions

Single instructions operate across a linear sequence. They iterate through a 1-dimensional array (like column definitions) and generate sequential elements like <th> headers or <col> width specifications. 

// single.json
[
  {
    "input": "columns",
    "targetPath": "base.children[0].children[0]",
    "template": {
      "tagName": "th",
      "textContent": "{{name}}"
    }
  }
]
2D Transformation

Double Instructions

Double instructions operate across a matrix plane. They iterate through two nested dimensions: data records along the Y-axis and columns along the X-axis, generating rows with properly bound data cells. 

// double.json
[
  {
    "rows": "data",
    "columns": "columns",
    "targetPath": "base.children[1]",
    "rowTemplate": { "tagName": "tr" },
    "cellTemplate": {
      "tagName": "td",
      "textContent": "{{row[col.field]}}"
    }
  }
]

The Power of Decoupling Logic from Code

Because instructions are JSON data:

  • No Rebuilding or Bundling: You can redesign a table layout or add classes without recompiling JavaScript.
  • Storage & Remote Delivery: Instructions can be stored in git (spec-repo) or fetched via an API.
  • AI & Visual Tooling: An AI assistant or a visual builder can inspect, generate, and edit instruction JSON files effortlessly.
