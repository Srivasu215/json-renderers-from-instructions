The Renderers: Breathing Life into the Spec

A specification tree is pure potential. The renderer is the master craftsman that translates abstract JSON nodes into living, interactive DOM elements on screen.

Input: Formed JSON Spec

The output from the instruction engine is a clean Virtual DOM tree. Every node is an object with a tag, attributes, and child nodes. 

{
  "tagName": "table",
  "attributes": { "class": "table table-striped" },
  "children": [
    { "tagName": "thead", ... },
    { "tagName": "tbody", ... }
  ]
}

Output: Living Browser DOM

@keshavsoft/json-to-dom mounts the spec into the document in a single atomic operation: 

// Atomic mounting
const dom = jsonToDom({
  jsonSpec: spec,
  targetHtmlId: "render-container",
  appendPosition: "replace"
});

// Result: Real HTMLTableElement

Why Plural: "Renderers"?

Notice that the repository is not called json-table-renderer. It is named json-renderers (plural).

That plural reflects the universal contract of the system:

  • Table Renderers: Multi-region tabular grids with sorting, headers, and rows.
  • Card & List Renderers: Responsive product cards, user avatars, or notification feeds.
  • Form Renderers: Input controls, dropdowns, and form bodies built from field blueprints.
  • Navigation Renderers: Menus, tabs, and breadcrumb structures.

Every single renderer follows the exact same contract: JSON instructions form the spec, and the renderer mounts it.
