The Benchmark

Why the Table Came First

This repository is not merely an HTML table generator. The table was chosen as the supreme stress test. Solving the table proves that instruction-driven rendering works for anything.

The 4-Zone Coordination Challenge

Unlike simple containers (<div>, <ul>), an HTML table is the most notoriously coupled component in the HTML standard. It demands simultaneous coordination across four independent regions:

1. <colgroup>

Defines width constraints and column-level styles across the entire grid.

2. <thead>

1D array of header cells with sort triggers and label text.

3. <tbody>

2D matrix of data rows, where each row must match column field positions.

4. <tfoot>

Summary aggregations, totals, or pagination controls spanning columns.

The Serial Number Proof

Consider a simple requirement: "Add a serial number column (#) to the table."

In imperative code, this requires:

  • Prepending a <col> to the <colgroup>.
  • Prepending a <th>#</th> to the <thead>.
  • Iterating through every single row in <tbody> and prepending a new <td>1</td>, <td>2</td>...

In our instruction architecture, this is handled purely by the options transformer: it simply updates the specification tree in memory before the renderer stamps it. Zero DOM reflows, zero imperative loops.
